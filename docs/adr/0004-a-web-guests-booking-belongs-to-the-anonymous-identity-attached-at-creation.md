# A web Guest's Booking belongs to the anonymous identity attached when it was created

**Status**: accepted, amended 2026-09-22 (see Amendment below); reads "the Admin" where it once said "the Host" (ADR-0007)

Ticket #13 asks the website to let a Guest upload their own government ID — and `firestore.rules` already decides who may write to a Booking: `isOwnDoc()` compares the document's `uid` to `request.auth.uid`, and the guest self-serve update rule allows only a fixed key list that deliberately does **not** include `uid`. So a Guest can change a Booking only if it was created carrying their identity, and can never add one afterwards. The website therefore signs the Guest in anonymously (`signInAnonymously`) at the moment `/book` creates the Booking, writes that uid onto the document, and uploads documents to `kyc/{uid}/{ref}/{kind}.{ext}` under the same uid — which is precisely what `storage.rules` assumes, so there is one address for one Booking's documents. The rejected alternative was to let a Guest claim an unclaimed document by proving knowledge of it (reference id plus name and email): reference ids are short, handed out in tracking links and easy to guess, and a rule that let whoever guesses one attach documents to — or withdraw — somebody else's Booking would trade a small inconvenience for a way to tamper with PII under RA 10173. The consequences to remember: Anonymous sign-in must be enabled in the Firebase console, or every web booking is created without an identity and web uploads are refused; a Booking made in one browser cannot be uploaded to from another, Bookings created before this change carry no `uid` and are permanently unlinked, so the Guest is told plainly to send the ID by email instead of being shown an upload control that would fail on a permission error; and in demo mode, where there is no Firebase at all, there is no identity and therefore no upload — the ID is never parked in a browser the Admin cannot read.

## Amendment (2026-09-22)

The `bookings` create rule now requires the document to carry a non-empty `uid`, so the first consequence no longer holds in its old form. With anonymous sign-in broken in a console, a web submission is refused at the write — the Guest sees the submission fail — instead of a Booking being minted with no identity, its uploads to fail later, and its reference id circulating unclaimable. The decision itself is unchanged: the Booking still belongs to the anonymous identity attached when it was created, a Booking made in one browser still cannot be uploaded to from another, and a Booking carried without a `uid` still cannot be claimed later. Only the failure mode moved — from silent (an unclaimable Booking) to loud (a refused write).
