# The approval re-check counts committed dates, not the waiting queue

**Status**: accepted

G2 requires the system to re-check availability when the Host approves a Booking, and the obvious reading — count every Booking that still holds those dates — makes a one-unit Accommodation unapprovable forever, because the Booking being approved is itself in the queue and the one behind it fills the last unit. So the re-check counts only the Bookings the Host has already *committed* the dates to (`Approved` and later), while the guest-facing availability read still counts everything holding them (`Pending` and `KYC Submitted` included) so a Guest is never offered dates that are already being reviewed. The consequence to remember: two Guests can queue for the same single unit and both be told the dates are taken, yet the Host can still approve either of them — the double-sell is prevented not by the queue but by the fact that once one Booking is committed, the unit is gone and the next approval is refused with the conflicting Bookings named. The Host therefore needs to see competing Bookings for the same dates before choosing, and the submit-time check is what keeps the queue from growing past the units available.
